# 实施计划 —— 第 3 步：人工报价

> 2026-09-17 ｜ 方案经需求方批准后实施

## 放哪

- 新域 **`domain/quote`**（文档 2 §2 目录规划里已有 `quote/ # 对客报价`），扁平，实现类 / 实体 / 仓库包私有
- 依赖方向 **quote → order 单向**：订单域发布 `OrderQuoting` 接口 + `QuotableOrder` / `QuotableLine` record，
  报价域调它读订单行、锁单、改状态；订单域不知道报价的存在（CLAUDE.md §2）
- 加成率放报价域自己的 `customer_markup` 表，不往 `organization`（platform/identity）加列（同文档 13 §3.5 的理由）

## 表（迁移 `2026-09-17_02_quote.sql`）

- `customer_order.status` 加 `QUOTED` / `CONFIRMED`（枚举加值，向后兼容）
- `customer_markup`：每客户一行
- `quote`：一次报价一行，`version_no` 从 1 起；发出时快照加成率；确认时快照汇率（来源、日期、EUR→CNY、EUR→对客币种）和总计；
  部分唯一索引「每单最多一条 SENT / 一条 CONFIRMED」
- `quote_line`：快照图号 / 名称 / 数量，原价；确认时写对客单价、小计

## 推导（不是给定的，前提写明）

- **CNY→对客币种**：ECB 只给 EUR→X，所以 CNY→X = (EUR→X) / (EUR→CNY)，两个值取同一天的批次；除法放最后、只取整一次
- **重报的版本状态**：`SENT` / `SUPERSEDED` / `REJECTED` / `CONFIRMED` —— 把「每次重报留一版」落成状态，名字是助手起的
- **确认时带回汇率日期**：「确认那一刻锁汇率」+「确认前价格随汇率变」合起来，客户看到的价和确认那一刻算出的价可能不同。
  为了不让客户确认一个没看过的价，确认请求带上他看到的汇率日期，不一致就 409 让他重看

## 并发

发出、确认、拒绝都先锁订单行（`FOR UPDATE`），同一张订单只能排队；加锁顺序「订单 → 报价」，和第 2 步一致。
库里另有部分唯一索引兜底。
