# 需求 —— 第 3 步：人工报价

> 2026-09-17

## 背景

第 2 步做完后，客户能提交订单（`SUBMITTED`），之后就没有下文：没有报价表，运营端报价页是原型假数据，
客户端报价页只显示「暂无报价」。第 3 步让一张单走完「运营报价 → 客户确认 / 拒绝 → 重报」。

## 需求方原话

- 「开始」（开始第 3 步报价）
- 之前已拍板的（设计文档 13）：原价人工定、逐行填单价；对客价 = 原价 × 汇率 × 客户加成率；逐行列价 + 总计；
  加成率每客户一个；币种每张报价现选；交期运营填、整单一个；汇率用 ECB，**客户确认的时候锁**。

## 本轮当面拍板（2026-09-17）

| 问题 | 定的 |
|---|---|
| 本轮范围 | **先只做人工报价**；AI 自动报价路径等 AI 估价、系数、阈值定了再加 |
| 加成率怎么填 | **填 1.2 = 乘 1.2**（0.9 = 九折） |
| 报价发出后 | **客户可拒绝，运营可重报**：拒绝 → 订单回到待报价；运营在客户确认前可改价重发；每次重报留一版 |
| 有效期 | **不设** |
| 可选币种 | **EUR / USD / GBP / CNY** |
| 交期形式 | **天数（客户确认后 N 天）** |
| 取整 | **对客单价保留 2 位，小计 = 单价 × 数量** |
| 客户页汇率展示 | **只提示「确认前随汇率变动」+ 汇率日期**，不显示汇率数字（也不显示原价、加成率） |

## 验收

- 运营能看到所有客户提交过的订单（草稿看不到），能看图（落审计）
- 运营设客户加成率；逐行填原价、选币种、填交期，能试算，能发出；重发时旧版作废、留记录
- 客户看到逐行对客单价、小计、总计、交期、汇率日期；确认前价格随最新汇率变
- 客户确认 → 汇率、单价、总计快照进报价，之后改加成率 / 来新汇率都不变；订单变「已确认」
- 客户拒绝 → 订单回到「已提交」，运营可再报
- 客户确认时汇率已更新（和他看到的不同）→ 拒绝，让他看新价
- 并发：确认和重报、确认和拒绝同时发生，只有一个成功
