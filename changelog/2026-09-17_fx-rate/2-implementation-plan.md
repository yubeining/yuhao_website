# 实施计划 —— 接入 ECB 汇率

> 2026-09-17 经需求方批准。

## 范围

**只取数、只存**：每天把 ECB 汇率拉下来存好、能查到。**不做**换算、锁定、buffer、对客价计算 —— 这些等第 3 步定政策。

## 形状

- 表 `fx_rate`（归属 `platform/fx`，设计文档 2 §2 早就规划了这个目录）：来源 / 公布日期 / 基准币 / 目标币 / 汇率 / 拉取时刻；
  唯一索引 `(source, rate_date, base_currency, quote_currency)`，写入 `ON CONFLICT DO NOTHING`
- `platform/fx`：解析器（JDK DOM，禁 DOCTYPE 防 XXE，格式不对整份拒绝）、客户端（JDK HttpClient，带超时和响应体上限）、
  写入组件（包内可见）、定时任务（§8 Redis 锁 + fence）、只读服务、运营端查询接口
- 配置 `app.fx`：开关、ECB 地址、超时；同步间隔在 `@Scheduled` 占位符里。测试 profile 关掉定时任务

## 我定的实现细节

| 细节 | 定的 | 理由 |
|---|---|---|
| 直接接 ECB，不经 Frankfurter | ECB 官方 XML | 同一份数据，少一个限流不透明的中间方 |
| 存哪些币种 | ECB 给的全部照存 | 挑哪些是业务决定；存全不需要决定 |
| 同步节奏 | 开机 1 分钟后一次，之后每 3 小时一次 | 数据每天只变一次；同一天重复拉只会跳过。工程取值，不是政策 |
| 超时 | 连接 10 秒、整次 20 秒 | 工程取值 |
| 拉取失败 | 只记 warn，不抛 | 汇率晚几小时更新不影响现有功能 |

## 被否决的方案

| 方案 | 为什么不用 |
|---|---|
| 用 Frankfurter 的 JSON | 多一层第三方，限流额度未公开 |
| 只存人民币 | 对客币种是每单现选的（文档 13 §2.3），存哪些不该由我定 |
| 顺手做 CNY→EUR 换算 | 四舍五入、锁定时点、buffer 都没定，做了就是替需求方定政策 |
| 回填 90 天历史 | 现在没有用处 |
| 过期告警（N 天没更新就报警） | N 没有依据 |
| 引入 WireMock 测外部 HTTP | JDK 自带 HttpServer 够用，不加依赖 |

## 顺序

迁移 → 本地应用 + psql 验约束 → 解析器（TDD）→ 同步 / 查询（TDD）→ 真网络实测 → 全量回归 → 提交 → 部署 → 线上验。
