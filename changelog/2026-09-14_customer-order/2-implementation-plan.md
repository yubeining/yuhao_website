# 实施计划 —— 第 2 步：客户订单 + 接客户端界面 + 第 1 步返修

> 2026-09-14 动手前经需求方批准。这里留结构、返修清单和被否决的方案。

## §A 第 1 步返修（评审发现，逐条核实过）

| # | 问题 | 改法 |
|---|---|---|
| A1 | 没有按图号查零件的接口，前端做不到 D16 的「按图号命中已有零件」 | `GET /customer/parts?code=` |
| A2 | 版本被订单引用后还能往里加文件，锁定形同虚设 | `part_revision.locked_at`；申请上传 / complete / 删文件三处都拒 |
| A3 | complete 读文件头时，S3 SDK（Apache 客户端）关流会把整个文件读完，期间占着数据库连接 | `StorageService.readRange`（HTTP Range）；存储 IO 移出事务 |
| A4 | complete 并发两次会 500（没有乐观锁处理器）；重试会 409 | 条件更新 + 幂等；全局乐观锁异常 → 409 |
| A5 | 拒收时先删对象再改状态，提交失败会留一行永远卡住的 PENDING | 先落 REJECTED，再删对象 |
| A6 | `getPart` 把没传完 / 被拒的文件也返回 | 只返回 COMPLETED |
| A7 | 审计没有业务上下文 | `context_type` / `context_id`；订单页看图校验归属后记上下文 |
| A8 | 下载的文件名是一串 uuid、没扩展名 | 下载签名带 `Content-Disposition`（原文件名清洗后） |
| A9 | 上传链接签进了 Content-Type，但回执没告诉前端要带哪个 | 服务端归一化，回执返回 `contentType` |
| A10 | 审计的访问方组织被硬写成图纸归属客户 | 拆成独立参数 |
| A11 | 前端没有任何错误码翻译 | `strings.ts` 补全部 code |

## §B 形状

- 迁移 `2026-09-14_01_customer-order-draft.sql`：订单状态 / 名称 / 期望交期 / 提交时间；订单行锁定版本、零件名称快照、
  材料、表面处理；版本锁定时间；文件 REMOVED；审计上下文。订单两张表至今无写入路径，线上必然是空表，加 NOT NULL 列一次发布安全。
- 接口：订单增查改、提交、取消；零件行增改删、换图纸；带订单上下文看图；按图号查零件；删文件。
- 前端：service 层（含浏览器直传 `putToSignedUrl`）；订单列表 / 订单详情 / 零件表单 / 首页 / 报价页 / 客户端外壳换真数据。

## 我定的实现细节（随方案一起批准）

1. 零件名称按订单行快照，草稿改名不回写零件主数据（C2）
2. 材料、表面处理放订单行上，不放图纸版本上
3. `part_no` 编号规则未定，暂填占位值，界面不显示
4. 草稿删行物理删；取消订单改状态
5. 图号精确匹配（只去首尾空格）
6. 同一零件同时出现在两张草稿里各自换图，会各开一个版本；草稿取消后版本号有空号
7. 保留第 1 步不带上下文的看图接口，界面不再用

## 被否决的方案

| 方案 | 为什么不用 |
|---|---|
| 版本在报价后才锁（原型口径） | 报价是第 3 步；本步提交后客户还能改图，运营看到的图随时会变 |
| 每次下单都重传图纸 | 需求方选了沿用上次锁定的图纸 |
| 材料做成下拉 | 材料主数据表不存在，下拉只能编选项（C5） |
| 客户端保留假数据演示开关 | 需求方选了客户端全换真；两套代码并存要多维护一份 |
| complete 继续用 `@Transactional(noRollbackFor)` | 事务里做存储网络 IO 会占连接；并发靠 `@Version` 会 500。改成无事务 + 条件 SQL |
| 状态机一次建全部 7 个状态 | 只建现在用得到的；枚举加值是安全的扩展，随第 3 步加 |
| 调高注册限流来让测试通过 | 那是改生产行为迁就测试。改成 HTTP 集成测试每个用例前清测试 Redis |
