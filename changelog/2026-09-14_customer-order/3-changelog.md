**第 1 步返修**：A1～A11 全部做完（清单见 `2-implementation-plan.md`）。要点：
- complete 改成**无事务 + 条件 SQL**：存储网络 IO 不再占数据库连接；并发 / 重试不会 500，已完成的直接返回
- 读文件头改用 **HTTP Range 只读 8KB**，不再把整个文件下载一遍

- 下载链接带原文件名（`DownloadFilename` 清洗：去控制字符、引号反斜杠换下划线、超长截断保扩展名、RFC 5987 编码）
- 全局乐观锁异常 → 409 `common.conflict`

**前端**：service 层（浏览器直传 `putToSignedUrl`，XHR 带进度、不带登录头）；订单列表 / 订单详情 / 零件表单 / 首页 / 报价页 / 客户端外壳全部换真数据；错误码翻译表；运营端、供应商端未动。

## 2026-09-15 测试后修复

需求方要求「测一下还有没有问题」。边界测试（本地后端）+ 浏览器 + 代码审阅，找到 7 个，都是第 2 步写出来的，线上都存在。

| # | 问题 | 严重度 | 修法 |
|---|---|---|---|
| 1 | **提交订单的同时加零件行 / 删掉最后一份图纸，两个请求都成功**，已提交的订单里出现没锁定、没图纸的行 | 严重 | 改订单的操作一律先 `SELECT … FOR UPDATE` 锁订单行；提交在锁订单之后、查图纸之前，再按 id 顺序锁各行的图纸版本；申请上传 / 上传完成 / 删文件在短事务里先锁版本再改状态，删桶里对象放在事务提交之后。加锁顺序固定「订单 → 版本」，文件操作只锁单个版本，不会死锁 |
| 2 | 非 UUID 的 id（旧书签 `SO-0001`）、错误 Content-Type、不支持的方法都回 **500** | 中 | 全局处理器补三类异常：400 `common.bad_request` / 415 `common.unsupported_media_type` / 405 `common.method_not_allowed` |
| 3 | **数量 `1.5` 被静默存成 1** | 中 | `spring.jackson.deserialization.accept-float-as-int: false`（Jackson 3.1.5 里有这个开关，已核实） |
| 4 | 订单页 / 零件页遇到非 404 的错误，**永远停在「加载中…」** | 中 | 加载失败显示错误和「重试」；400（id 格式不对）和 404 一样按「不存在」处理 |
| 5 | 编辑页的图号输入框看着能改、打字没反应 | 低 | 改成纯文字显示 |
| 6 | 「取消订单」没有确认，点了不能撤销 | 低 | 取消前 `window.confirm` |
| 7 | 两个 PATCH 接口是整体替换，没带的字段会被清空 | 低 | **不改行为**，接口注释写明；前端每次都带全部字段 |

### 修 #1 时自己踩的一个坑

往 `application.yml` 加 Jackson 开关时新建了一个 `deserialization:` 块，而文件里原本就有一个 —— YAML 重复键，
所有集成测试的 Spring 上下文都起不来（0.27 秒全部报错）。合并进原有的块后恢复。
