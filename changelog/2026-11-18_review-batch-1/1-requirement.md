# Review 第一批修复 —— 需求

## 背景

2026-11-18 对整个项目做了一轮 review（AI 估价 / 后端 / 前端三部分各一个独立审查，最重的几条由主审自己读代码或实测核实）。
需求方原话：「先修第一批」；方案确认时：「监控指标接口 不改 其他按照你的方案来」。

## 本批范围（会丢数据或有安全风险的）

| # | 问题 | 定的做法 |
|---|---|---|
| 1 | 删草稿订单会连带删掉已提交订单的图纸 | 只删未锁定、且没被别的订单用着的图纸版本 |
| 2 | 旧的「邮箱 + 密码」注册接口不验证邮箱归属，可被抢注 | 默认关闭（404），只在测试环境打开 |
| 3 | `/actuator/prometheus` 对公网开放 | **不改**（需求方决定） |
| 4 | 图纸提交锁定后还能用旧上传链接替换 | 上传完成时把对象挪到新地址，旧地址删除 |
| 5 | 验证码每日全站 100 条，被刷满后所有人登录不了 | 已注册邮箱不占、不受这个额度限制（需求方选 A） |
| 6 | 供应商退单 + 运营撤回分配后，该供应商订单列表一直 500 | 找不回上游的行只显示自己还有的字段 |
| 7 | AI 估价不校验模型给的数 | 负数 / 空元素 / 类型不合约定 / 金额超出字段范围 → 判为「AI 没有给出可用的结果」 |
| 8 | AI 估价的资源风险 | 图片先读尺寸再解码；模型调用 60 秒超时、不重试；同时最多 2 个估算；后端检查订单状态 |

## 验收

每一项有一个先失败、修后通过的测试；全量 `mvn verify` 通过。
