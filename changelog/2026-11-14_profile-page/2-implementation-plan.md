# 实施计划 —— 个人资料页（2026-11-14）

## 后端

1. `GET /{customer|supplier|ops}/me/profile` → email / nickname / partyType / createdAt
   - 三端各一条路径（路径前缀即受众），id 只从 principal 取
   - 返回字段白名单，不返回密码、租户内部字段
2. `PATCH` 同路径，请求体只有 `nickname`；外部用户与运营账号两张表都更新

## 前端

1. `pages/ProfilePage.tsx`：昵称（可编辑）+ 邮箱/身份/注册时间（disabled）+ 保存
2. 顶栏头像菜单加「个人资料」，路径由设置页路径推导（`/settings` → `/profile`）
3. 设置页删掉「账号」卡片（连退出登录按钮一起，退出登录顶栏菜单里已有）
4. `Input` 组件补 `disabled` 属性 + `.inp:disabled` 置灰样式

## 关键取舍

- **只有昵称可改**：邮箱是登录标识（换绑要先证明新旧邮箱都归本人）、身份由组织类型推出、
  注册时间不可变。这三项置灰展示，不加「暂不支持」之类解释文字。
- **一个页面一张卡**：不拆「基本信息 / 账号 / 登录与安全」，不写 hint 文案。
- **保存后写 session**：顶栏直接读 session.displayName，写回即可立刻生效。

## 被否决的方案

- **放在设置页里编辑**：设置是偏好，个人资料是账号，混在一起就是当前的问题。
- **加「设置密码」「更换邮箱」**：需要新的产品规则（无密码账号、双邮箱验证），本次不做。
- **三张卡 + 头像大图 + 说明文字**：第一版 mock 的做法，被需求方判定为蛇足。
