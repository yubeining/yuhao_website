# 变更记录 —— 生产订单

## 概念

```
客户订单 SO-xxxx        客户说「我要这些」
      │  零件
      ▼
  未安排零件池          客户确认报价后落进来
      │  运营挑（可跨客户订单）
      ▼
生产订单 PO-xxxx        我方说「这一批交给一家做」
      │  挂到订单市场
      ▼
  供应商整单抢走 → 一份合同 → 排产 → 按行报工
```

**两个概念不再重合**：一个 PO 可以装多个 SO 的零件，一个 SO 的零件也能分散进多个 PO。

## 行为上的几处硬规则

| 规则 | 为什么 |
|---|---|
| 挂出去之后行就定死，不能加减 | 供应商是照着挂出来的那一版抢的，改行等于换合同标的（C2） |
| 行上存快照不存引用 | 同上 |
| 退回 / 调价是整单的 | 一个生产订单一个供应商，没有「只退一行」这回事 |
| 调价填的是统一涨幅 % | 一单几十行，逐行改价等于重组一遍 |
| 排产整单确认，报工按行 | 他按整批安排产能，但各行进度本来就不一样 |
| 发货、回款登记按客户订单 | 都是对客户的动作；PO 里可能装着别人的零件 |
| 应付日按行看 | 几个客户各付各的，没有一个共同的时刻 |
| 市场上不出现图号、不出现客户 | 文档 7 §8 脱敏；跨客户之后更不能带客户信息 |
| 卡片和详情页不给平均单价 | 各行单价本就不同，平均值不对应任何一件东西 |

## 验证

`npm run type-check` / `npm run build` 通过。

浏览器实测（客户 A 一张 3 零件订单 + 供应商 A 一张 2 零件订单，均已确认报价）：

| 场景 | 结果 |
|---|---|
| 未安排零件池 | 5 个零件，跨 2 个客户订单，各自带图号和来源订单 |
| 跨客户组包 | 勾选 2 个不同客户的零件 → 底部提示「跨 2 个客户」→ 组成 PO-0001 |
| 组包后 | 池子从 5 减到 3；PO-0001 详情页显示「2 个客户 · 2 行」并有跨客户提示条 |
| 挂出 | PO-0001 open，抢单截止 +24 小时；两个客户订单都变成「已安排生产」 |
| 市场（供应商视角） | 只显示「法兰盘 等 2 个零件 / 304 不锈钢 · 40Cr 合金钢 / 共 35 件 / 整单 ¥5,811.30」——**没有图号，没有客户** |
| 整单抢走 | PO-0001 taken，生成 CT-0001，金额 ¥5,811.30 |
| 按行报工 | 两行分别报满 → PO done |
| 客户订单汇总 | 两张客户订单都显示「生产中」——各自还有零件没安排，不会误报成已完成 |
| 运营订单页 | 两张客户订单的「生产订单」列都指向同一个 PO-0001 |
| 退回 | PO dropped，行上的零件回到未安排池 |

node 侧另跑了一遍纯逻辑，额外覆盖：一个客户订单的零件分散进 PO-0001 和 PO-0002。

## 遗留项

1. **设计文档 3 §2.4 已经和实现对不上，需要改**：那里写的是
   `production_order` 挂单个 `order_id`、且「一个订单行可对多个生产订单」。
   本次两条都被业务方推翻（能跨客户订单、数量不拆）。文档没动，等一并修订。
2. **「整单开一张票、但回款按行顺延」这个组合需要业务方确认。**
   合同是一单一份，票也是一张；但几个客户各付各的，所以应付日按行算。
   真实结算怎么走（等全部客户回款再付整单？还是按行分批付？）没定。
3. 抢单超时**没有自动退回** —— `dropProd` 现在只能运营手动点。
   定时任务属于后端范畴，当前阶段不做。
4. 客户订单里被退回的零件会重新出现在池子里，但**客户那边没有任何提示**说
   「这几个零件还在找产能」。要不要告诉客户、怎么措辞，没定。
5. 生产订单目前没有名字/备注字段，只有编号。运营组包时可能想标一句
   「这批走加急」—— 需求没提，没加。
