# 实施计划（动手前对齐，2026-09-20）

## 定下来的做法

| 决定 | 理由 |
|---|---|
| 状态只存在**叶子零件行**上，三张单的状态每次操作后从叶子行重算回写 | 文档 12 §1：叶子是唯一的真状态机。多存一份就多一处要同步 |
| `customer_order_part` **存**折叠后的四态 | 客户端要按它筛，现算要跨三层零件链；文档 12 §8 要求同事务同步 |
| `ops_order_part` **不存**状态 | 可由叶子行现算，运营页面直接算。**与文档 12 §7 的表格不一致，是刻意取舍** |
| 原行合格 0 件时件数不动、状态改 `SUPERSEDED` | 库里 `quantity` 的 CHECK 是 `>= 1`，减不到 0 |
| 返工 / 重做行**不写对供价快照** | 成本供应商自担（文档 12 §5），合计仍是接单时锁定的数 |
| 客户零件行「进行中」以**第一次开工**为准，不是接单 | 接单后还可能退单 / 收回；用开工做起点就不需要在取消路径上回滚状态 |
| 所有写操作先 `FOR UPDATE` 锁生产订单 | 和接单 / 签字 / 退单同一把锁、同一个顺序，不引入新的加锁顺序 |

## 被否决的方案

- **给客户零件行的状态做实时计算（不落库）**：每次列表都要跨三层零件链查，且客户端要按状态筛。否决。
- **为返工件重新算对供价**：需求方定的是供应商自担，重算等于自己发明计价规则。否决。
- **在叶子行上记「返工次数」**：没人要求，拆行本身已经能数出来。否决（Simplicity First）。
- **把质检拆成独立的 `qc_record` 表**：本轮质检结果就是行上的状态 + 件数，没有报告、没有附件。
  等质检报告 / 材质证明（文档 12 §10）定了再拆。否决。
