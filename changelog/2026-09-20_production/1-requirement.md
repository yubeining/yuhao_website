# 需求 —— 第 6 步：生产进度 + 质检

## 原话

> 开始下一步 生产进度和质检

随后四个问题，需求方本人当场选的（2026-09-20）：

| 问 | 答 |
|---|---|
| 本轮做到哪 | **做到质检完成**（供应商开工 / 完工 → 发给我们 → 运营质检 → 客户端看到进度）。发给客户（物流单号、客户确认收货）下一轮 |
| 报工粒度 | **只报「开工」和「完工」**，不报件数 |
| 报废补料 | 本轮只做**原厂重做**（同一家、供应商自担）；「换一家做」和差价扣款下一轮 |
| 发货条件 | **整单全部完工才能**点「发货给平台」 |

## 背景

第 5 步之后，供应商签完字单据就锁定了，然后没有下文：没人能报进度，货到了也没地方记质检，
客户端看到的还停在「已确认报价」。这一步把一张已签字的单推到「全部零件质检合格」。

质检本身的规则不是这次定的，来自设计文档 12 §1 §5 §7 §8（按件数记合格 / 返工 / 报废、
返工另开一行、数量守恒、客户只看四态）。

## 验收

1. 供应商：每行能报开工、完工；所有行完工后能「发给平台」，没完工时点不了并写明原因。
2. 运营：看得到已签字之后的单和每行进度；对到平台的行填 合格 / 返工 / 报废（三个数之和 = 件数）。
3. 返工件、报废件从原行拆出来另开一行，溯源两头都记得住；报废件能点「原厂重做」补一行。
4. 每一步之后「活跃件数 + 还没补料的报废件数 = 客户要的件数」。
5. 全部合格后：供应商订单已完成 → 生产订单已完成 → 客户订单「待发货」。
6. 客户只看得到 待安排 / 进行中 / 已完成，看不到返工、报废、供应商。

## 不在本轮

发给客户（物流单号、客户确认收货）· 换一家做（RESOURCE）和差价扣款 · 报废赔付 / 结算 ·
质检报告和材质证明 · 通知 · 供应商按件数报进度。
