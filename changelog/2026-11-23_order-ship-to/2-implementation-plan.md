# 订单收货地址 —— 实施计划（2026-11-19 出方案，2026-11-23 获批）

## 调研

| 来源 | 地址字段 | 对我们的参考 |
|---|---|---|
| Shopify | 国家、姓名、公司、地址行 1/2、城市、州/省、邮编、电话；公司 / 地址行 2 / 电话可配「不显示 / 选填 / 必填」 | 地址行 2 只放楼层门牌，不能必填 |
| Amazon（Buy with Prime 接口） | 国家用 ISO 两位代码，地址行 1、扩展地址、州/省、邮编 | 国家存代码 |
| Google libaddressinput | 每国必填项不同（美国要州和邮编，瑞士不用州，有的国家不用邮编） | 州/省、邮编不能一律必填 |
| 淘宝 / 京东 | 收货人、手机号、省市区、详细地址、默认地址 | 国内习惯；地址簿是便利功能 |
| DHL（ShipEngine 对接文档） | 收件公司必填、收件人、电话、完整地址；部分国家要税号 | 跨境发货电话、公司基本必需 |
| Xometry / Protolabs | 查不到表单字段 | 无可借鉴 |

## 字段

国家/地区（ISO 3166-1 两位代码）、收货公司、收货人、电话、地址行 1、城市 必填；地址行 2、州/省、邮编 选填。

## 改动

1. 迁移：`customer_order` 加 9 个可空列（只加列，无需扩展-收缩）；同步 `schema.sql`、迁移 README。
2. 后端：`CustomerOrder` 加字段；新增 `ShipTo` 视图；`OrderView` / `OpsOrderView` 带上地址；
   `PUT /customer/orders/{id}/ship-to`（整体替换，DRAFT～CONFIRMED 可改，READY / CANCELLED 409 `order.ship_to_locked`）；
   提交时没地址 400 `order.ship_to_required`；国家代码对 `Locale.getISOCountries()` 核对。
3. 前端：客户订单详情「收货地址」卡片 + 编辑弹框（C7）；运营报价工作台只读卡片；中英文案和错误码文案。
4. 测试：集成测试覆盖提交拦截、各状态可改 / 不可改、字段校验、租户隔离、运营可见、供应商不可见。

## 被否决 / 暂缓

- 一个多行文本框：需求方要求参考电商格式，拆字段。
- 客户地址簿 / 默认地址、按国家校验邮编、清关税号：第一版不做。
