## 这套文档是什么

给一个「欧洲客户 → 我们 → 中国供应商」三方协作的非标机加工业务，设计一套官网 + 交易平台。
技术栈已定：**React (Next.js) + Java 21 / Spring Boot 3.5 + PostgreSQL + Redis**。

架构参考自 WeAct 项目（同栈，3200+ Java 文件、529 个 migration 的生产系统），
但**只借鉴被事故验证过的部分**，明确剔除其中的技术债。第 4 篇是逐项裁决清单。

## 一页纸摘要

**业务链路**

```
欧洲客户 ──传图纸/RFQ──▶ 我们后台 ──匿名化寻源包──▶ 供应商（个位数，强制上系统）
                              ◀────────报价─────────┘
                        综合 + 定价算法
   ◀──对客一口价── 我们后台
   客户点接受 = 正式订单 ──▶ 拆生产订单（同一零件可拆多家）──▶ 供应商生产
                          ──▶ 我们质检 ──▶ 包装 ──▶ 第三方物流 ──▶ 欧洲客户
账款：线下走，平台只记录状态，不收款不清分
```

**部署形态**

> ⚠ **本节已被实现修订。**设计稿原本是 4 个独立部署单元，其中 `portal` 用 Next.js。
> 实现时改为 **`portal` + `backend` 合并为一个部署单元**，前端换成 Vite + React SPA。
> 理由见 [`../../CLAUDE.md`](../../CLAUDE.md) §2。下表是修订后的形态。

| 单元 | 内容 | 技术 |
|---|---|---|
| `backend` + `portal` | 唯一后端 **+** 客户端/供应商端/内部后台 | Spring Boot 3.5 / Java 21，托管 Vite 打出的 React SPA。**一个 jar、一个容器** |
| `site` | 公司官网（获客、SEO、多语言） | SSG，独立域名。**仍然独立** —— 它的存在理由就是 SEO |
| `cad-worker` | CAD 转换 / 图纸脱敏 / 水印（sidecar） | 独立容器，Phase 2 才需要 |

**六个已拍板的决策**

| # | 决策 | 影响 |
|---|---|---|
| D1 | 数据可存亚洲单区，无欧盟驻留要求 | 架构成本减半；存储位置做成可配置，预留将来拆分 |
| D2 | **客户点接受 = 正式订单** | 报价即要约，必须上五道护栏（见文档 3 §4） |
| D3 | 同一零件可能拆给多家供应商 | `订单行 ↔ 生产订单` 多对多，QC 按拆分粒度判 |
| D4 | 对客先只看一口价 | 报价单 MVP 不展开分项，但内部必须存全量分解快照 |
| D5 | 供应商个位数，强制上系统 | 邀请制开户；不做招投标/评分算法；**必须手机可用 + 微信通知** |
| D6 | 返修/退货/索赔 MVP 不做 | 订单状态机保持简单，但预留 `REWORK` 挂载点 |

**三条不可妥协的红线**

1. **图纸访问全审计** —— 谁、何时、看了哪个版本、从哪个 IP。这是跟欧洲客户签保密协议时的交付物。
2. **供应商端 response 白名单序列化** —— 只允许显式列出的字段，默认不暴露。漏一个字段就是泄露客户身份或对客价。
3. **一切锚定图纸版本（PartRevision），不锚定"最新"** —— 制造业最经典的事故是"按 Rev B 报的价、按 Rev C 生产"。
