# 8 — AI 自动报价与动态定价

> 编写日期：2026-08-17 ｜ 状态：设计稿
>
> **这不是一个新模块，是[文档 6](./6-供应商派单模式变更.md) §3.1「内部成本估算」的升级版。**
> 那一步现在是人工填复杂度表算系数，本文档把它自动化，并定义精度契约与反馈闭环。
>
> 依赖：D2（客户点接受＝正式订单）、D9（方案甲：先锁供应商再报客户）、
> 文档 3 §2.3（定价规则是数据不是代码）。

---

## 1. 链路

```
零件（图纸 + 材料 + 数量 + 公差 / 表面处理 + 交期）
        ↓  AI
   基准价 = 这个零件的制造成本      ← 精度契约：±30% 以内，覆盖 95% 的零件
        │
        ├──→ × (1 + 议价空间)  ─────────────→  给供应商的目标价
        │
        └──→ + 一系列成本 + 利润率(可配) ──→  对客价（动态定价）
```

**基准价是制造成本，不是对客价。**这一点必须在实现里保持清晰，
否则"利润率"会被混进模型，模型就再也说不清自己在预测什么。

---

## 2. ★ 精度契约：±30% @ 95%

### 2.1 标签定义（分母是什么）

「零件的实际价格」在业务上是观察不到的量。**能观察到、且正是我们要预测的，
是"供应商会以什么价接这一单"。**所以：

| | 定义 |
|---|---|
| **标签** | 供应商**首次接受**的价格 |
| **剔除** | 加急单、返工单、因产能临时压价/抬价的异常单 |
| **口径** | 单件价，同一零件不同批量分开记 |

我们要预测的不是零件理论上值多少钱，是**供应商会不会按这个价接单**。
这个定义让标签天然可得：每一次接单都产生一条样本，零额外成本。

### 2.2 ±30% 相对毛利是什么概念

现行毛利 22%。**基准价差 30%，超过整个毛利。**
所以这个精度能不能用，完全取决于**这个数字流到哪里去**。

### 2.3 为什么在方案甲下这个精度够用

```
AI 基准价 → 目标价 → 派给供应商 → 供应商接受（真实成本锁定）→ 才算对客价
                                          ↑
                                 模型误差在这里被市场纠正
```

**对客价是按供应商实际接受价算的，不是按 AI 估的价算的。**
模型误差到不了客户那一端 —— 这正是 D9 选方案甲带来的额外收益。

### 2.4 这条契约同时回答了 Q12

文档 6 留了个待确认项 Q12：「成本估算偏差到什么程度才考虑切方案乙」。

**答案：±30% 的情况下绝对不能切。**方案乙下模型误差直接落到对客价上，
而客户点接受即成合同 —— 低估 30% 就是按亏本价签了合同。
**要切方案乙，精度至少要进到 ±10% 以内**，且需要连续三个月稳定。

## 3. ★ 误差方向不对称 —— 本文档最重要的一节

同样是 30% 的偏差，两个方向后果完全不同：

| 偏差方向 | 会发生什么 | 能否发现 |
|---|---|---|
| **低估** | 目标价太低 → 没人接 → 派单超时 → 调价重派 | **立刻暴露**，代价是时间 |
| **高估** | 供应商秒接（白赚），对客价偏高 → 丢单 | **几乎发现不了** |

**高估才是隐蔽的杀手**：钱悄悄多付了，单悄悄丢了，系统里一片祥和。
所以模型评估不能只看绝对偏差，**必须分方向统计**，并且对高估施加更大的惩罚。

### 免费的定价反馈：接单耗时

```
派单时刻 ──────────────► 接单时刻
              Δt
```

- **Δt 很短（秒接）** → 目标价大概率给高了
- **Δt 接近超时** → 目标价接近供应商的底线，给得刚好
- **超时无人接** → 给低了

这个信号每一单都在产生，不用等财务对账，也不用额外录入。
**`supplier_invitation` 表必须记 `dispatched_at` 和 `accepted_at`**，
这两个字段是定价模型的免费训练信号。

## 4. 从基准价到两个价格

### 4.1 → 供应商目标价

```
目标价 = 基准价 × (1 + 议价空间)
```

议价空间现取 **+6.7%**，含义是"留给供应商的接单动力"。它应该是可配置的，
并且**可以按供应商分档**（产能紧张的厂需要更高的动力）。

### 4.2 → 对客价（动态定价）

```
对客价 = 制造成本 + 一系列成本 + 利润率
                                   ↑ 动态的是这一项
```

**制造成本**：报价前用基准价预估；**供应商接单后换成实际接受价重算**。

**一系列成本**：做成**可配置的成本项清单**，不写死在代码里。
现已知六项；「运营人工」（评审 / 跟单 / 客服分摊）待定，先占位不启用。

| 成本项 | 状态 |
|---|---|
| 到货质检 / 包装 / 国内运费 / 出口费用 / 国际运费 / 关税 | 已启用 |
| 运营人工分摊 | **待定**，字段先留 |

加成本项不发版 —— 延续文档 3 §2.3「定价规则是数据不是代码」。

### 4.3 动态定价 = 利润率按客户分档

**动的是利润率，不是成本。**因为不同客户对价格的敏感程度不同。

| 档位 | 毛利 | 适用 |
|---|---|---|
| A 档 | 16% | 价格敏感 · 长期大批量 |
| B 档 | 22% | 标准 |
| C 档 | 28% | 低频 · 小批量 · 急件多 |

落地方式：`pricing_rule` 已经有 `MARGIN_TIER_*`，只需要扩一个
**「交易方 → 档位」**的映射，以及档位的生效区间。

**D2 的硬约束**：报价一旦发出，有效期内价格不能变。
所以动态定价**只作用在"生成报价的那一刻"**，之后档位改了也不影响已发出的报价 ——
这正是 C3（历史单据自包含）要求把 `margin_tier` 快照进报价行的原因。

## 5. 模型要能说"我没把握"

**95% 是总体指标，但你需要知道是哪 5%。**

每次估价必须同时输出：

```json
{
  "basePrice": 230.58,
  "range": { "low": 205.40, "high": 261.80 },
  "confidence": 0.87,
  "modelVersion": "PRICE_CNC_v4",
  "similarSamples": 34
}
```

**置信度低于阈值 → 不出价，直接转人工估价。**
一个会说"这个零件我没把握"的模型，比一个闷头报 95% 准确率的模型有用得多 ——
它把错误挡在了外面，而不是混在总体指标里。

**分品类看短板，不看总分。**例如非金属件（密封 / 塑料）样本少、离散大，
准确率只有 71%，就应该**整类转人工**，而不是拉低总体后继续硬报。

## 6. 冷启动与演进

**一开始没有数据。**

| 阶段 | 做法 |
|---|---|
| **v0 · 规则** | 仅一那套复杂度算法 + 你们的工时测算，做成规则版本。**同时开始采样** |
| **v1 · 拟合** | 样本够（建议 ≥ 300 条同品类）后，用特征拟合替换规则 |
| **v2 · 学习** | 引入几何特征，持续用接单结果回流 |

**接口从 v0 起就固定成 §5 那个结构**，换实现时不动上层。

**采样必须在 AI 做出来之前就开始。**规则版跑的每一单也要记
「估了多少 / 实际接受多少 / 偏差」，否则真要做模型时手上没有数据。

---

## 7. 模型输入需要什么

| 来源 | 特征 |
|---|---|
| **清单**（文档 7） | 材料、数量、公差等级、表面处理、热处理、交期 |
| **三维模型** | 包围盒、体积、去除率、最小内圆角、孔数与交叉孔、面数、薄壁比例 |
| **历史** | 相似零件的成交价、该供应商的报价习惯 |

几何特征要从 STEP 里提取，需要 CAD 内核 —— 就是架构里已经规划的
**`cad-worker` sidecar**（文档 2）。这是它除了脱敏与预览之外的第二个用途，
也是把它提前到 Phase 2 的理由。

## 8. 新增数据结构

```sql
price_estimate                        -- 每一次估价都留档
  id, rfq_item_id, part_revision_id
  base_price_cny     numeric(14,4)
  range_low, range_high
  confidence         numeric(5,4)
  model_version      text             -- ★ 快照，不引用当前模型
  feature_snapshot   jsonb            -- ★ 当时喂进去的特征
  estimated_at, estimated_by          -- by = 'model' | user_id
  fallback_to_manual boolean

price_feedback                        -- 标签回流
  id, price_estimate_id
  supplier_quote_line_id
  accepted_price_cny numeric(14,4)    -- 标签：首次接受价
  deviation_pct      numeric(6,2)     -- (估 − 实) / 实
  time_to_accept_sec bigint           -- ★ 接单耗时信号
  excluded           boolean          -- 加急 / 返工 / 异常单剔除
  excluded_reason    text
```

`model_version` 和 `feature_snapshot` 必须快照，理由同 C3：
半年后复盘"当时为什么估成这个价"，不能依赖当前的模型和配置。

## 9. 对路线图的影响

| 阶段 | 做什么 |
|---|---|
| **Phase 1** | 规则版估价（v0）+ **`price_estimate` / `price_feedback` 两张表就位开始采样** |
| **Phase 2** | `cad-worker` 提取几何特征；估价接口不变 |
| **Phase 3+** | 样本够后换拟合模型；上线「估价模型」监控页 |

**采样表要在 Phase 1 就建。**这是整件事里唯一"晚做就补不回来"的部分 ——
模型可以以后再训，但没记下来的历史单价永远找不回来了。
